# Host-local resource lanes (v0 implementation)

`borg lane --json job submit --spec -` accepts an engine-neutral JSON `JobSpec` and returns a job ID immediately. `borg lane --json job wait ID` blocks on the supervisor's kernel lock, returns the terminal status and exits nonzero on failure. Use Borg's existing command watcher for long waits rather than repeatedly asking an agent to poll `status`. `job status [ID]`, `logs ID` (log path), `cancel ID`, `recover [--dry-run]`, `resource list|status|set-capacity`, and `service ...` are also available. `--state-dir` or `BORG_LANE_DIR` overrides the host-local state root; the service root is `ROOT/services`. Do not move a live root between hosts.

The journal is atomically renamed under a stable `flock` inode and records monotone ticket sequences, pending-only full-spec coalescing, shared slot capacities, FIFO exclusion, generation-fenced leases, supervisor evidence, reasoned RAM/disk admission and quarantine. Disjoint resources admit concurrently; an earlier conflicting exclusive ticket blocks later shared work. Job and service RAM/disk reservations are rechecked under the same journal lock using `workspace::assess_budget`, with disk reservations grouped by filesystem device; rejected service attempts leave a bounded, reasoned terminal record without occupying FIFO; failed system inspection queues the request rather than granting it. Kernel completion locks identify owners after crashes; recovery kills only a verified owned cgroup or PID/start-time and quarantines anything unverifiable. Never remove stable lock files while active.

Systemd **user scopes** are the production workload and service isolation path. If no user manager is available, the runner refuses unscoped execution unless `BORG_LANE_DEGRADED=1` is explicitly set for testing. Workloads are argv arrays, not shell snippets. In the service handoff, each backend supervisor claims a `service:<id>` shared lease *before* starting and retains its FD until backend stop. Every exclusive job automatically snapshots all matching active service IDs, reserves its FIFO place in `Preparing`, requests each service to restore client settings, stop its owned backend and yield its shared lease, then rechecks release under the journal lock before granting. New backend starts and timed resumes are refused while `Preparing` or exclusive `Granted` blocks the resource. Optional pre-hooks cannot substitute for this check. For a bound service, a post hook completes before the job releases its resource; a post failure quarantines the resource and does not falsify the workload exit status. After terminal completion a detached resume worker tracks `resume_pending` until the service is actually Healthy, not just until its Resume RPC removes the yield token. An unreachable, stopped or unready backend leaves a reasoned `resume_error`; the bounded 30-second readiness wait is outside the journal lock, and `job recover` retries by inspecting status without sending Resume twice. Services with longer readiness timeouts can remain pending until later recovery. Inspect and resolve quarantines manually; never infer safe recovery from a PID alone.

Direct model-facing unrestricted `lane_submit_job`/`lane_acquire` MCP tools are **not** enabled here: authorization, adapter validation and ownership remain an integration boundary. The supported agent path for now is validated CLI specs plus Borg's existing command watcher; workspace hygiene has a separately gated optional MCP bridge. The engine adapters and manifest parser are separate work. Project/Worktree resource scopes require existing absolute canonical paths at ticket and service-spec ingress: `..` and symlink aliases are rejected before they can create a second lock identity. The capacity CLI canonicalizes its path before calling the store; direct store calls reject noncanonical capacity keys. Service admission is host-local and depends on all adapters using the same canonical resource keys. Idle/stopped services have no running backend to yield, but still must reacquire the lane gate before any restart.

Verification: `CARGO_BUILD_JOBS=6 nice -n 10 cargo test -p borg-lanes -- --test-threads=1` (26 passed); strict lane Clippy, `cargo fmt --all -- --check`, and `python3 crates/borg-cli/tests/test_lane_process.py target/debug/borg` (6 passed). The process suite uses fake workloads (no game engine), including FIFO, pending-only coalescing, RAM/disk admission, failed pre-yield, Project/Worktree alias rejection, and verified owned-scope crash recovery.

Independent real-systemd public CLI probes on pre-readiness binary SHA-256 `011c4ba94835500d40910d3dab6096533d245a55f0ea7f72c1112b1450e5e99d` passed: Project `..`/symlink and Worktree path-alias rejection; canonical Project same-key exclusive yield, proxy503/client restoration/restart fence, then service resume; disjoint-key two-service RAM reservations denied the second with a reason and no backend, then admitted it after the first yielded. The same pre-readiness binary passed failing post-hook quarantine (exit 42; neither backend relaunched) and stopped-supervisor failed-resume/recovery retry.

On the post-readiness binary SHA-256 `61ece6c173170b080933c821b81658a3d8ad422b1a5601d9550f8a30c4d7d4ac`, independent real-systemd probes passed two-service same-device disk reservation denial (no second backend, reasoned wait) and later admission after the first yielded; Project alias rejection and canonical same-key service handoff; scoped two-service no-hook handoff with detached descendants; and stopped-supervisor failure leaving visible `resume_pending`/`resume_error` until restart plus `job recover` cleared both. Earlier pre-budget service probes passed ordered successful post-hook barrier. The same binary passed independent public ACK-then-unhealthy recovery: a fake service health toggle caused Resume RPC to consume its yield token while the backend stayed unready; the job retained `resume_pending` / `resume_error` after the bounded wait, and health restoration plus `job recover` cleared both without another Resume RPC. Failing post-hook quarantine was confirmed on the earlier binary and awaits replay on this one. The 26 unit tests include a targeted missing-token/unhealthy-then-Healthy recovery regression. These fake-service probes do not establish Unreal Editor parity.

Per-agent `WorkspaceBudgets` dispatch caps are a documented v0 limitation deferred to v0.1, not a release gate; host-wide job and service reservations are enforced here. Model-facing MCP authorization and session-derived editor-owner fencing remain integration responsibilities, not provided by this crate.

# Game-development coordination interface contract (v0)

Status: **interface skeleton, not a working lane**. Rust declarations compile in
`crates/borg-lanes`. Implementers should rebase on `gamedev/design` and keep
implementation in their owned files. CLI/MCP bindings below are planned APIs,
not present on this branch. Changes to shared types go through gd_architect;
prefer additive fields and explain wire compatibility.

`borg-lanes` is host-local, engine-neutral policy/execution. Workspace event
stream owns shared claims/decisions, session event stream owns tool invocation,
local supervisor owns processes/locks. A project path is canonicalized once,
prior to comparison; host identity is implicit in local resource keys. Project
scope names the canonical project root or identity file consistently across
worktrees (e.g. Unreal installation resource uses `Host`, build output uses
`Worktree`, and editor state uses the canonical main `Project`). Path aliases
must not create separate locks. Reject relative/untrusted outside-root paths
at adapter validation and revalidate symlinks at execution. No separate cloud
coordination database.

## Resource, ticket, lease, job

The Rust surface is `lanes::{ResourceScope,ResourceKey,Capacity,Access,
ResourceRequest,Holder,LeaseRequest,Ticket,Lease,AdmissionBudget,JobSpec,
JobHandle,LaneCoordinator,JobCoordinator}`. Keys can be host/project/worktree;
`Capacity {key,slots}` bounds shared slots (global caps are host keys).
`Access::Exclusive` consumes the whole key, and shared consumes `slots`.
Normalize/aggregate duplicate keys before enqueue; reject zero or over-capacity
requests. A multi-key request admits **atomically**, never while holding one
key waiting for another. Tickets have monotone sequence, persisted before
admission; among *conflicting requests*, do not grant a later ticket before an
earlier eligible one. Disjoint resources may proceed concurrently; no
priority bypass or retry race. Cancellation/timeouts unblock the next ticket.

`Holder` identifies participant and session, but a session going away does not
make a running job's process tree unowned. The supervisor owns a lock FD for
each granted lease (Linux `flock`, on a stable lock inode, `CLOEXEC` on spawned
children) and an individual per-job systemd user scope. A lease JSON token is
only a locator, **not** proof of ownership; hold the actual lock until the job
or service yields/releases. Supervisor restart takes recovery lock, scans
journal/scopes/lock FDs, and reconciles first. Never unlink live lock inodes.
Scope names are generated by Borg and checked against recorded unit identity;
only Borg lane-owned scopes can be stopped. If `app-borg-workloads.slice` is
present, join it; otherwise use the user's normal slice. Apply `MemoryMax` and
an actual timeout to the entire process tree. On non-systemd hosts use a
platform-specific equivalent with proven process ownership, otherwise refuse
unsafe recovery; never signal arbitrary name-matching UBT/editor PIDs.

`JobSpec` stores argv (not a shell string), cwd, env, fingerprint, resource
request, budget, memory cap, timeout/stall timeout and bounded pre/post hooks.
`submit` returns an existing pending job with the same fingerprint when
`coalesce`; join a running one only after rechecking input revision against
its start snapshot. Fingerprint includes canonical tree, source revision or
content/mtime snapshot, target/config/flags, compiler version and output
policy. Failed-result reuse is separate opt-in adapter policy, never assumed
by coalescing. All subscribers receive the same terminal exit and bounded
log. Hooks are explicit executables in their own tracked scope; pre hooks
must succeed before dispatch, post hooks cannot falsify a finished job's
status. Serialize engine-specific UBT startup with a separate host resource;
release it after the startup hazard passes, not after the entire build.

RAM/disk: check `MemAvailable` and free space on the actual output filesystem
at dispatch, deduct current reservations, add safety margin, reject/queue with
an actionable budget reason, and release reservations exactly once. Budgets
apply to worktree creation, jobs and resident services. Refuse pathological
settings rather than exceeding memory; do not turn queue admission into an
agent-side sleep/retry loop. Per-worktree output estimates count toward disk
reservations. Persistent disk usage is reconciled after crashes.

State layout: `${XDG_RUNTIME_DIR}/borg/lanes/{state.json,queue.jsonl,
locks/<hash>.flock,jobs/<uuid>/{spec.json,events.jsonl,output.log},
services/<id>/{state.json,events.jsonl,output.log},recovery.jsonl}` with
0700 directories/0600 files and atomic replace + fsync of critical admission
state. If XDG runtime storage is ephemeral, completed job history/logs move to
`${XDG_STATE_HOME:-~/.local/state}/borg/lanes/`; restart recovery treats lost
runtime metadata conservatively. No credentials in logs; bounded redaction.
Do not equate event records with active kernel locks or healthy process scopes.

## Service contract

`services::{ServiceSpec,HealthCheck,RestartPolicy,Endpoint,ServiceState,
ClientLease,ServiceStatus,ServiceCoordinator}`. Supervisor starts in a user
service/scope not tied to caller session. Validate health (bounded timeout,
interval) before switching traffic. `Stopped → Starting → Healthy | Failed`;
`Healthy → Degraded | Yielding | RestartPending`; `Yielding → Yielded →
Starting`; `RestartPending → Restarting → Healthy | Degraded | Failed`.
Crash loops use bounded backoff and max restart count; an explicit trigger
(coalesced after debounce, e.g. build output changed) may restart. Expose
reason, backend, owner, log and next retry in status.

A stable loopback endpoint fronts alternating backend ports A/B. For restart,
launch B, verify health, atomically switch new connections, drain A and stop
it; a failed B leaves A serving. Existing connections may need reconnect
based on upstream protocol. Protect proxy and backends under the same ownership
boundary; only the proxy binds the public loopback endpoint. If the service
requires exclusive project access, `yield_for` drains clients and stops the
backend **before** the exclusive resource is granted; revalidate held leases
before resume. A client lease has owner identity and expiry. Every owner-
scoped setting records prior state and a bounded restore callback; restore on
release/expiry/crash, including PIE/cvars. A restart cannot silently discard
unrestored settings. Healthy status is not proof that a raw MCP call respects
client lease: adapter MCP proxy must enforce owner on every mutating call.

## Workspace contract

`workspace::{WorktreeSpec,WorktreeRecord,CachePolicy,FreezeRequest,Freeze,
WorkspaceCoordinator}`. `create` first checks budget and a branch/path claim,
then `git worktree add`; record owner, base ref, projected output, actual
filesystem usage, idle time. `gc` is dry-run by default at CLI, excludes dirty,
locked, active, pinned and user-created trees and never deletes manually
without explicit owner confirmation. Clean only owned generated outputs first
when pressure builds; `cargo clean` or Unreal output cleanup requires the
owning worktree's active jobs to end. Prefer sharing immutable downloaded
artifacts, not writable build output. Cargo registry/target sharing is safe
only with cargo's own locks or separate target directories; CMake and UBT
intermediates stay tree-private; Unreal DDC is shared through its native
cache; ccache may be shared using its own concurrency semantics. Explicit
`Private`, `SharedReadOnly`, `SharedLocked` policies govern caches.

A freeze is a *coordination protocol*, not a magical Git lock. First create
and claim one `shared_work` item; declare dependencies for blocked tasks.
Requester names affected paths, rationale and deadline, asks all relevant
owners to acknowledge, then takes an exclusive project/refactor resource to
block new protected jobs. Existing jobs drain; unsaved changes are never
rewritten by another agent. Freeze commits a reviewed refactor, notifies
owners with new base, and releases the gate; failures/timeouts require explicit
abort/recovery and notification. Relevant `claim_shared_work`/
`declare_work_dependency` remain the durable authority for task ownership.
The local freeze record links the shared work ID and participant acks rather
than replicating that authority. An unresponsive owner's dirty worktree is
not deleted or rebased automatically.

## Adapter contract and examples

`adapter::{AdapterManifest,JobTemplate,JobKind}` is a version-0 parsed model;
Blu is the packaging and trust boundary (see `docs/blu-extensions.md`).
Package declares project markers, resource keys, job templates with argv
placeholders and typed inputs, run/test exclusivity, supervised services,
cache policy, skills and allowlisted MCP servers. Initially ship validated
adapter config as data in a Blu package, with workflow-backed `borg lane`
commands if a manifest parser is not yet wired; **do not pretend `api` v1
already accepts `[api.lanes]`**. Extending Blu declarative schema requires a
versioned validation/migration change. Never pass arbitrary template argv,
paths or MCP tools from an untrusted project to a privileged supervisor.

| Engine | Resource keys | Jobs | Service/cache |
| --- | --- | --- | --- |
| Unreal | host UBT startup; per-worktree build output; canonical project run/editor exclusivity; host RAM slots | UBT build `-NoMutex`, `-MaxParallelActions` from RAM; headless run/commandlet exclusive project; test automation | editor MCP with A/B endpoint, PIE/cvar owner restoration, post-build restart; shared Zen DDC, tree-private intermediates |
| Unity | per-project Library import; license/editor seat host cap; tree build | batchmode build/test, exclusive asset import | resident editor/bridge where supported; Library tree-private |
| Godot | per-project import cache; scene/project writes | headless export/test, resource scan | optional editor RPC; per-tree `.godot`, shared immutable downloads |
| cargo/CMake | per-target dir; host CPU/RAM; test fixture keys | cargo build/check/test; cmake build and ctest `-j`, fixture-exclusive tests | cargo registry/ccache shared under native locks; target/build dirs isolated |

## CLI, MCP, and non-polling waits

Proposed CLI: `borg lane resource list|status`, `borg lane lease acquire
--project P --resource K [--exclusive] [--wait]|release ID|status ID`, `borg
lane job submit|wait ID|status ID|logs ID|cancel ID|recover --dry-run`,
`borg lane service start|status|lease|release|restart|yield|resume|stop`,
`borg lane workspace create|list|gc --dry-run|freeze|ack|unfreeze`. Bare
`acquire`/`submit` return a ticket/job ID immediately; `--wait` blocks on
supervisor event notification, with queue timeout and a terminal exit code.
Do not block a model tool call indefinitely to wait for a job.

Lanes worker's **implementation draft** uses `borg lane job submit --spec
SPEC.json --json` (or `--spec -` for stdin), `borg lane job wait JOB_ID
--json`, `borg lane job status [JOB_ID] --json`, and global `--state-dir` /
`BORG_LANE_DIR`. `SPEC.json` is serialized `JobSpec`; shell adapter paths
should construct/validate it, never forward raw model argv. The earlier
`--adapter/--template` CLI shorthand is future validated-template sugar, **not**
part of the draft CLI. `wait` blocks on a kernel lock and returns job exit
status, so a model-facing workflow submits first and watches the CLI wait
command rather than invoking a long synchronous workflow.

Proposed MCP tools and minimal JSON schemas (required shown, optional in
brackets): `lane_submit_job {adapter:string,template:string,project:string,
inputs:object,[idempotency_key:string]} → {job_id,ticket,state,log_path}`;
`lane_acquire {project:string,resources:[{name,scope,access,slots?}],
[queue_timeout_ms:number]} → {ticket_id,state,lease_id?}`;
`lane_status {id:string} → {state,holder?,queue_position?,log_path?}`;
`lane_release {lease_id:string}`; `lane_cancel {id:string}`;
`lane_service {op:start|status|lease|release|restart|yield|resume|stop,
id:string,[ttl_ms]}`; `lane_workspace {op:create|list|gc|freeze|
ack|unfreeze,project:string,[path],[work_id],[dry_run]}`. The holder is
derived from the authenticated session, never supplied as a model field.
Model-facing `gc` is dry-run only until an exact human approval is bound in
Borg durable state. Input validation,
authorization and capability checks happen before supervisor side effects;
list/status/logs are scoped to allowed workspace. Never expose an unrestricted
`argv` field to model-facing tools.

**Wait integration:** there is one event authority per ticket/job, replayable
by sequence; event registration performs snapshot-then-subscribe atomically so
a just-finished job cannot strand a waiter. CLI `job wait` blocks on the
supervisor's notification FD/socket. For agents, `lane_submit_job` returns a
job ID immediately, then `watch` runs `borg lane job wait ID` with
`notify_on=exit` (or a future typed job subject on Borg's watcher channel),
and the agent calls `await_watchers` **only** when no other work is actionable.
On exit the watcher emits terminal result/log pointer even for failure, and
wakes a yielded goal; if already terminal it exits immediately. `await_watchers`
is opt-in, requires an active goal and a live watch; an explicit human stop
preempts wake. Existing `watch` is session-scoped and max four watches; avoid
one watcher per ticket by allowing a batch `job wait --any ID...` and implement
first-party typed watch subjects in runtime if necessary. For another agent's
completion use `watch` with `agents` / `wait_agent`, **not** a file/port watch.
A mere `lane_status` or log-file artifact is not a safe substitute for a
producer-aware watch. See `docs/watcher-yield.md` and runtime `watch.rs`.

## Decisions log

- D1: one engine-neutral crate, four independently owned modules, no adapter
  implementation in the core. Minimize cross-branch conflicts.
- D2: local lock FD + scoped supervisor is the execution authority; workspace
  shared-work stream remains the coordination authority.
- D3: immediate IDs plus event-driven blocking CLI/watch, no polling tools or
  mandatory indefinite MCP calls.
- D4: Blu `api` v1 does not contain lane declarations; adapter data and
  validation are an explicit integration milestone, not silently assumed.

- D5: gd_lanes_core owns CLI entry (`cli.rs`/`main.rs`) and lanes command
  module; services/workspace may own isolated subcommand modules but route
  integration through lanes owner. No direct agent-runtime MCP edits in v0;
  Blu workflow-backed CLI is the initial agent bridge. MCP bindings above
  remain follow-up work until end-to-end permissions and tests exist.
- D6: service additions (health kind, idle/readiness controls, richer status)
  are additive. Standalone borg-services crate rejected; keep cross-module
  resource/yield types in borg-lanes. Detached supervisor must retain lock FD
  and kernel-backed ownership across requesting process exit.

- D7 (pending implementation): stale lease holders must be fenced after
  supervisor recovery, expiry or exclusive yield. Attach a monotonic per-key
  grant generation (or equivalent owner-validated token) to mutations,
  validate it at the service proxy and release path, and reject stale clients;
  a UUID and a log entry alone are not an authorization proof. gd_lanes_core
  and gd_services_core will agree the additive Rust field before landing.
- D8: VCS-native binary asset locks (P4, UVCS, Git LFS, etc.) remain
  authoritative for edit checkout; host lane resources do not replace them.
  Adapters must gate mutating asset actions against project VCS policy.

- D9: lanes owner fixed draft CLI as JSON `JobSpec` via `--spec` and a
  blocking `job wait ID` command; adapters must not assume `--adapter` and
  `--template` shorthand until validated template admission is implemented.
  Model-facing tools must validate/admit named templates rather than accept
  untrusted arbitrary process argv.
- D10: model-facing service mutation tools are held for final integration,
  not implemented independently in the services branch. A safe dispatcher
  derives holder from authenticated session, permits only pre-registered
  service specs, and authenticates owner/fence on every mutation; until that
  boundary is reviewed, CLI plus status-only inspection is the supported
  bridge. A model-supplied `owner` or `confirmed` boolean cannot confer
  participant authority or human approval. Workspace destructive MCP GC is
  dry-run only until approval is bound to the exact deletion.
- D11: editor service/exclusive-job mutual exclusion is a *shared lane
  resource*, not merely a `yield` status flag. The service must stop its
  backend and release its shared project lease before the exclusive request
  becomes Granted; the exclusive holder releases before service resume can
  reacquire. A pre-hook that runs *after* grant is too late to prove this
  ordering. No editor+exclusive parity claim until both owners demonstrate
  this handshake under crash/restart and identical canonical root/key.
